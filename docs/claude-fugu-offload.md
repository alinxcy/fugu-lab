# Claude → Fugu 外注プレイブック(Claude の負担を減らす)

Claude(実装エージェント)が、機械的な下請けを **Fugu base** に投げて自分はレビューと
判断に集中するための指針。実測(下記)に基づく。

## 大原則: 「生成が重く・検証が軽い」タスクだけ外注する

外注のコスト会計:

```
外注で節約 = (自分で生成するコスト)
外注で発生 = (委任prompt作成) + (出力の検証・手直し) + (Fugu API 実費)
→ 生成が大きく機械的、かつ検証が自動化/安価なときだけ純利益
```

つまり **「出力を結局ぜんぶ精読しないと使えない」タスクは外注しない**
(それなら自分で書くのと変わらない)。検証が `実行/スキーマ検証/完全一致` で
自動化できるものが最優先。

## 実測(fugu base・全て裏0・3〜11秒)

| タスク | 検証法 | 結果 |
|---|---|---|
| JSONL パーサ生成(壊れ行スキップ) | 実行してテスト | ✅ recs=2/skip=1 正動作 |
| 仕様文 → 構造化 JSON 抽出 | JSON スキーマ検証 | ✅ 3件・スキーマ適合 |
| 日本語携帯番号の正規表現 | pos/neg で実行 | ✅ 6/6 |
| 翻訳 JA→EN | 目視 | ✅ 自然な技術英語 |
| 要約(1文) | 原文照合 | ✅ 忠実・簡潔 |

base fugu は裏0で速く正確。**検証が機械化できる下請けは安心して投げられる。**

## 外注してよい ✅ / 手元に残す ⛔

**✅ 外注(base fugu)** — 検証が安いもの:
- 定型コード生成(パーサ/変換/CRUD雛形) → **実行・テストで検証**
- フォーマット変換・構造化抽出(自由文→JSON/表) → **スキーマ検証**
- 正規表現・SQL・簡単な shell/jq → **サンプルに当てて実行**
- 翻訳(JA↔EN)・言い換え・トーン調整 → 目視スポットチェック
- 一次要約・ドラフト(あとで自分が整える前提) → 原文照合
- テスト雛形・ダミー/サンプルデータ生成 → 実行

**⛔ 手元に残す(Claude)** — 検証が生成と同じくらい重い/判断が要る:
- アーキテクチャ・設計判断、トレードオフの決定
- セキュリティ上重要なコード(生成物を全行精査する羽目になる)
- 会話文脈・ユーザー意図に依存する統合/最終回答
- 仕様そのものの執筆(妥当性判断が本体)
- 「壊れたら静かに誤る」類(このプロジェクトの集計ロジック等)

## 運用のコツ(実測でハマった点の回避)

- **「コードのみ」「訳文のみ」「JSONのみ」と明示する。** base fugu は
  「Sakana AIが開発した…」等の**冗長な前置き**を付けがち。出力形式を縛ると減る。
- **思考過程(CoT)が出力に混ざることがある**。機械処理する前に
  コードブロック抽出・JSON部だけ切り出す等の**サニタイズを噛ませる**。
- **max_tokens は余裕を持つ**。reasoning がトークンを食うため、ケチると途中で切れる。
- **ultra は外注に不向き**。裏80〜97%・数秒〜7分・本文空リスク・**制御不能**
  (別紙 `fugu-findings.md` §5.6)。外注の下請けには base 一択。
  ultra は「専門家チームを1発で回したい高価値タスク」を人間が明示指名するとき限定。

## 実際に外注する道具: `tools/fugu_offload.py`

毎回ハーネスを書き下ろすと、その手間が外注の利益を食う。CLI に固定してある。

```bash
# コード生成 → そのまま実行検証できる(前置き・フェンスは除去済み)
python tools/fugu_offload.py --task code --prompt "関数 human_bytes(n) を書け" > out.py

# 構造化抽出 → そのまま json.tool / jq にパイプできる
python tools/fugu_offload.py --task json --prompt "次から [{task,owner,due}] を抽出: ..." | jq .

# 正規表現 → そのまま re.compile できる文字列だけ返る
PAT=$(python tools/fugu_offload.py --task regex --prompt "郵便番号にマッチ")

# 標準入力も食える(長い原文の要約・翻訳)
cat draft.md | python tools/fugu_offload.py --task summary --prompt "次を1文で要約:"
```

設計上の要点:

- **既定で chat アプリ経由**(`FUGU_CHAT_URL`、既定 `http://127.0.0.1:8150`)で叩く。
  つまり **外注 1 回ごとに UsageRecord が JSONL に追記される** — 作業がそのまま測定データになる。
  アプリ未起動なら直接 API にフォールバックするが、その場合は記録されない旨を stderr で警告する。
- `--task` が「出力形式の縛り」と「サニタイズ方法」を同時に決める。
  前置き・コードフェンス・CoT 漏れを落としてから stdout に出すので、**パイプで次段に繋げる**。
- 実測値(elapsed/表/裏/裏率)は stderr に出る。stdout は成果物だけ。
- 既定モデルは `fugu`(base)。ultra は外注に不向きなので明示指定しない限り使わない。
- `--effort`(high/xhigh/max)は**明示時のみ**送る。効果は未確定(要追試)なので既定では送らない。

実測(この CLI 経由・すべて裏0):

| task | 例 | 検証 | 結果 |
|---|---|---|---|
| code | `human_bytes(n)` | 実行 | ✅ 11.7s / 前置きなし・そのまま動作 |
| json | 文 → `[{task,owner,due}]` | `json.tool` | ✅ 9.8s / 有効 JSON |
| regex | 郵便番号 | `re.compile`+pos/neg | ✅ 8.3s / `\d{3}-\d{4}` 全判定正 |
| summary | stdin パイプ | 原文照合 | ✅ 3.5s / 忠実 |

## ルーター(擬似コード)

```
def route(task):
    if task.needs_judgment or task.security_sensitive or task.is_final_synthesis:
        return CLAUDE                      # 手元でやる
    if task.verification in {execute, schema, exact_match} and task.generation_is_bulky:
        return FUGU_BASE                   # 外注(裏0・速い)＋自動検証
    if task.is_high_value_open_synthesis and human_opted_in:
        return FUGU_ULTRA                  # 例外的に。コスト/遅延/空返しを許容
    return CLAUDE                          # 迷ったら手元
```

## このユーザーの常用作業への当てはめ(観測+推測)

- 仕様(SPEC)からのタスク/要件抽出 → **JSON化を base に外注**、判断は Claude。
- 定型コード・テスト雛形・サンプルデータ → **base に外注**して実行検証。
- ドキュメントの JA↔EN 翻訳・要約下書き → **base に外注**、最終調整は Claude。
- スキル/エージェント定義や仕様の執筆・設計判断 → **Claude が担当**(外注しない)。
- ベンチのグレーダや集計ロジック → **Claude**(静かに誤ると致命的)。

> まとめ: base fugu は「速くて正確で裏0の下請け」。**検証が自動化できる機械的生成**を
> 投げれば Claude はレビューと判断に集中でき、実質的に負担が減る。
> ultra はこの用途には高コスト・不確実すぎるので使わない。
